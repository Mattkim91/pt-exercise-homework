# 운동 영상 QR — 이후 계획

지금은 출력하지 않는다. 출력 옵션의 QR은 꺼진 채로 잠겨 있고, 표시는 「향후 출시 예정」이다. 예전 기록에 QR이 켜져 있거나 운동에 영상 주소가 있어도 유인물에는 QR을 넣지 않는다. 운동별 영상 주소 입력과 `exercise-homework-video-defaults-v1`도 화면에서 쓰지 않는다. 주소가 기록에 남아 있어도 읽기만 하고 깨지지 않게 둔다.

`vendor/qrcode.js`, `qrDataUrl()`, 유인물의 QR 마크업은 그대로 있다. `QR_RELEASED`가 `false`인 동안 `qrOnLeaflet()`는 항상 거짓이라 그 경로는 실행되지 않는다.

## 영상이 준비되면

1. 운동마다 짧은 영상을 만들어 저장소에 둔다. 파일 이름은 운동의 `imageKey`와 맞춘다. 예: `videos/diaphragmatic-breathing.mp4`.
2. GitHub Pages에 운동마다 자기 페이지를 둔다. QR은 mp4 파일을 직접 가리키지 않고, 그 페이지를 가리킨다. 페이지에서 해당 mp4를 재생한다.
3. 그때 `QR_RELEASED`를 켜고, 출력 옵션의 QR을 다시 켤 수 있게 한다. 켠 유인물에서만 운동마다 그 페이지의 QR이 나온다.

## GitHub Pages 용량

- 파일 하나당 GitHub 한도는 100MB이고, 50MB를 넘으면 경고가 난다. 영상은 그 한도에 가깝게 만들지 않는다.
- GitHub Pages 사이트는 1GB 안쪽을 권장한다. 운동이 약 80개이므로 한 편을 1–3MB(짧은 길이, H.264, 가로 약 640px)로 두면 전체는 대략 80–240MB다. 10MB를 넘기지 않는 쪽을 기본으로 한다.
- Pages 월간 전송은 약 100GB가 부드러운 상한이다. 짧은 영상이어야 여러 환자가 QR로 봐도 여유 있다.
- Git LFS에 넣은 파일은 Pages가 영상으로 내려주지 않는다. mp4는 저장소에 일반 파일로 둔다.
